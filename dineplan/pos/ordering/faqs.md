# FAQ's

## 1. How do I start a new order for an available table from the POS home screen?

To start a new order for an available table:

1. From the DinePlan home screen, click **POS**.
2. The POS screen displays the available tables and their status colors.
3. Identify the table for which the customer wants to place an order.
4. Verify that the table status color is **White** (Available).
5. Click the required table button.

<figure><img src="../../.gitbook/assets/image (286).png" alt=""><figcaption></figcaption></figure>

**Result:** Because the table does not have an active order, the **Ordering screen** opens automatically for creating a new order.

**Note:** If you select a table with a **Yellow** status, it already has an active order, and the system will display the existing order instead.

## 2. What do the White, Yellow, and Brown table status colors mean on the POS screen?

Table status on the POS screen is indicated by three distinct display colors:

* **White:** The table is available (no active order).
* **Yellow:** The table is occupied (has an active order in progress).
* **Brown:** The table is waiting for payment (bill print taken / order submitted).

## 3. How do I select a menu category and add menu items to an order?

To browse categories and add items requested by a customer:

1. On the **Ordering screen**, review the available menu categories.
2. Click the required category. The menu items configured under that category display on screen.
3. Review the items listed under the selected category and click the required menu item.
4. Verify in the **Order Summary** panel that the correct item has been added.
5. Repeat the process for all items requested by the customer.
6. Select another menu category when additional items are required from a different menu section.

## 11. What is the difference between Select Customer, Create Account, and Close on the New Customer screen?

When working on the **New Customer** screen, choose an action button based on your immediate task:

* **Select Customer:** Directly selects the newly created customer and links them immediately to the current active transaction.
* **Create Account:** Creates a customer account in the system database so that the customer becomes available in the general **Customers** list for future orders.
* **Close:** Closes the **New Customer** screen without linking or creating an account.

**Note:** Use **Select Customer** when the customer is present and paying for the current transaction; use **Create Account** when setting up a general account record for future visits.

## 24. Which specific user actions automatically submit an active order in DinePlan?

DinePlan automatically submits the current order whenever any of the following three actions are performed:

1. **Closing the Ordering screen**
2. **Changing the table**
3. **Printing the bill**

**Note:** Because these actions submit the order, always complete your pre-submission review checklist before executing any of them.

## 25. What happens if I add more menu items to a table after the initial order has been submitted?

After an order is submitted (by closing the screen, changing tables, or printing the bill), any additional items subsequently added to that table are automatically treated as a **new order**.

**Workflow:** `Existing Order` → `Submit Order` → `Add New Item` → `New Order`

## 41. What is the operational difference between Void, Comp, and Gift?

DinePlan provides three distinct item-level operations based on item status and user permissions:

* **Void:** Used when a customer cancels an item that has **already been sent to the kitchen**. Selecting **Void** requires entering a reason in the **Reason/Void** field and clicking **OK**. The cancellation notice is automatically sent to the kitchen so the chef stops preparing the item.
* **Comp:** Used when an item has **already been prepared** by the kitchen and cancelled, meaning it cannot be reused or resold. Requires entering a reason in the **Reason/Comp** field and clicking **OK**.
* **Gift:** Used when an item is provided to the customer **free of charge** (such as a promotional item). Selecting **Gift** requires entering a reason in the **Reason/Gift** field and clicking **OK**. The item price automatically updates to **zero**.

## 45. What happens if I add additional items to a table after the order has already been submitted?

When new items are requested after order submission:

1. Any action such as **closing the Ordering screen**, **changing the table**, or **printing the bill** automatically submits the current order.
2. If the customer subsequently requests additional items, opening that table and selecting new items automatically creates a **new order** batch.
3. The new items are managed as a separate order sequence for that table (`Existing Order` → `Submit Order` → `Add New Item` → `New Order`).
